# TGPI Home Page Blueprint v1

## 1. Purpose

The TGPI Home Page is the primary transition point between public content and the product experience.

It must receive users coming from Instagram and immediately preserve brand continuity, trust, clarity and strategic authority.

The Home Page is not a generic landing page. It is the main institutional and conversion interface of TGPI.

Its job is to help a new visitor understand, within seconds:

1. what TGPI is;
2. what problem it solves;
3. why the platform is different;
4. what the visitor can do next;
5. why creating an account is useful.

---

## 2. Primary User Journey

```text
Instagram content
→ link in bio
→ TGPI Home
→ understand the product
→ explore countries or compare options
→ create account
→ onboarding
→ dashboard
→ recurring use
→ Premium conversion
```

The Home must therefore optimize for both understanding and progression.

---

## 3. Core Positioning

TGPI is a global decision platform for people who want to study, work, live, travel or build an international life with greater clarity.

The Home must not position TGPI as:

- a travel blog;
- a country directory;
- a generic online school;
- an immigration consultancy;
- a promise of legal, financial or relocation outcomes.

The Home must position TGPI as:

- a practical global education platform;
- a structured country decision system;
- a global readiness environment;
- a product that connects data, education, mobility and identity.

## 5. Home Page Conversion Strategy

The Home must use a progressive conversion model.

### Stage 1 — Recognition

The visitor must recognize the same visual identity found on Instagram.

### Stage 2 — Comprehension

The visitor must understand what TGPI does without reading long paragraphs.

### Stage 3 — Demonstration

The visitor must see real product surfaces: countries, comparison, readiness, profile and documents.

### Stage 4 — Action

The visitor must receive a low-friction action before being asked to create an account.

### Stage 5 — Account conversion

Account creation should be presented as the way to save progress, receive recommendations and build a global profile.

# 12. Visual System

## Color ratio

```text
70% off-white / white
20% navy
10% gold and supporting accents
```

## Typography

### Display

Serif institutional typography for major headings.

### Interface

Sans-serif typography for body, navigation, data and controls.

## Photography

Use realistic, high-resolution imagery related to:

- global cities;
- universities;
- airports and mobility;
- libraries;
- documents;
- international work;
- cultural environments.

Avoid generic tourism clichés and inconsistent color grading.

## Cards

Use a limited system:

```text
EditorialCard
MetricCard
CountryCard
DecisionCard
FeatureCard
```

## Motion

Motion must support hierarchy, not decoration.

Allowed:

- subtle reveal;
- hover elevation;
- image scale within controlled bounds;
- progress animation;
- reduced compact header on scroll.

Respect `prefers-reduced-motion`.

# 16. Accessibility Requirements

- WCAG AA contrast minimum;
- semantic landmarks;
- one H1 only;
- logical heading order;
- visible keyboard focus;
- descriptive alternative text;
- accessible mobile menu;
- minimum touch target of 44x44px;
- reduced motion support;
- no critical information conveyed only through color;
- forms with explicit labels and error states.

---

# 17. Performance Requirements

- maintain `next/image` for product imagery;
- define image sizes and responsive `sizes`;
- avoid large above-the-fold JavaScript bundles;
- keep Home sections server-rendered unless client behavior is required;
- lazy-load below-the-fold interactive content;
- avoid autoplay video in the initial version;
- prevent layout shift;
- keep first viewport visually complete before loading secondary sections.

Target quality direction:

```text
LCP: under 2.5s
CLS: under 0.1
INP: under 200ms
```

These are product targets and must be validated in production rather than assumed from local builds.

---

# 18. Security and Trust Requirements

The Home must:

- use HTTPS production links;
- avoid false institutional claims;
- avoid unsupported user or revenue statistics;
- expose legal and privacy links;
- distinguish educational content from professional advice;
- never expose Firebase or billing secrets;
- route account and payment actions through protected existing flows.

# 20. Definition of Done

The Home Page is complete only when:

- the visual identity is recognizably consistent with TGPI Instagram;
- a new visitor can explain TGPI after the first two sections;
- primary product areas are demonstrated with real interfaces or data;
- all CTAs lead to valid and intentional destinations;
- mobile navigation and all sections work at 360px width;
- authenticated and unauthenticated states remain functional;
- TypeScript returns zero errors;
- ESLint returns zero errors and zero warnings;
- production build succeeds;
- accessibility checks pass the agreed standard;
- analytics events are verified;
- no unsupported claims or placeholder statistics remain;
- the Blueprint and implementation match.

---

# 21. Decisions Still Requiring Founder Approval

Before final visual implementation, the founder should approve:

1. final hero headline;
2. primary Home CTA;
3. exact product proof shown above the fold;
4. whether Documents receives a dedicated route before launch;
5. which Premium features are launch-ready;
6. whether testimonials or partner proof are available and verifiable;
7. final photography set;
8. final footer legal routes;
9. whether the Home prioritizes account creation or country exploration;
10. whether the current Instagram language remains English-only across the site.

Until these decisions are approved, implementation should use reversible components and avoid hard-coding unsupported content.
